# 0.2.0 worklog — offset slider rework + PNG export

## What was built

Two upgrades on top of 0.1.0:

### 1. Plot-width offset slider under the plot

Replaced the tiny browser-default range input with a 1037x40 canvas-based slider
sitting directly below the grid, inside `#plotWrap`. Visuals:

- background bar (gray) at y=18, height=6
- green "active range" fill from the today marker to the thumb (forward if
  offset > 0, backward if offset < 0)
- quarter-year tick marks at -52, -39, -26, -13, 0, +13, +26, +39, +52 weeks
- "-52w" / "+52w" end labels
- vertical "today" tick at the midpoint with a "today" label
- rounded thumb (12x22) with a thin grip line; centered on the offset value
- hover label (a positioned `<div>`) shows the resulting start/end date
- hover guide line over the track

Interaction:

- `pointerdown` anywhere on the track jumps offset to that week
- `pointermove` while down continuously updates offset (`setPointerCapture`)
- keyboard: arrows ±1 (Shift = ±4), PageUp/PageDown ±13, Home -> 0,
  End -> ±52, all when the track has focus
- `wheel` over either the plot or the track scrubs offset: 19 px = 1 week,
  scroll down = move into the past
- all paths funnel through `setOffset(v)` which is the single mutator:
  clamps, updates DOM readout, recomputes dates, refreshes suggestion,
  schedules both plot and track re-render, debounces save

Geometry stays aligned to the plot: `TRACK_INSET = LABEL_W`, `TRACK_USABLE =
W * PITCH`, so the slider thumb sweeps exactly the plot's column range.

### 2. PNG export

New "PNG" button next to Export. Generates a 2x scaled copy of the plot
(no border, no padding) into an offscreen canvas and downloads
`timeplot-<startISO>-<endISO>.png` via a data URL. Uses the same drawing
pipeline as the on-screen render via a shared `renderGridToCtx(ctx, scale)`
helper, so colors / future dimming / today outline stay in sync.

The on-screen grid uses its own draw loop (it touches the live `ctx` and
the existing legend/rect-overlay code); the PNG helper duplicates the cell
loop only because it's invoked from a fresh, scaled transform. The PNG does
not include the today outline or rect drag preview (those are transient)
or the actual-commits dots (those need a fetched user, separate concern).

## Notes / decisions

- The track is drawn on a separate `requestAnimationFrame` batch so dragging
  it doesn't force a full plot re-render every frame — but the offset
  itself triggers both, since changing dates affects the plot.
- The "fill" on the track is purely visual (green = current range from
  today); the actual semantic is just the thumb position. Kept it because
  it makes "+5 vs -5" instantly readable at a glance.
- Wheel listener is `passive: false` on the canvas and track only (not the
  whole page) so the rest of the page scrolls normally.
- `setOffset(v, {force: true})` is used during init so a saved offset is
  reflected even if it equals the default 0.
- PNG filename includes the date range, so a user with multiple saved
  offsets gets unambiguous files.
