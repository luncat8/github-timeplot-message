# 0.1.0 - GitHub Timeplot Message - Dev Plan

## Goal

No-build vanilla JS app that lets the user paint a 53x7 grid styled exactly like the
GitHub contributions graph. The painted grid is a *plan*: each cell's level maps to a
number of commits on a real calendar date, so the user can paint a message or picture
and then receive per-day commit-count suggestions to make the profile render it.

## Draft Requirements (parsed)

- same style plot as on github
- input line for text or draw rectangles with pointer
- slider to move date related to image. horizontally, by set week.
- buttons fill, clear
- draw tools: draw, erase
- slider to adjust draw amount.
- amount is relative and draw color related to max amount.
  example: 0,1 -> 0,255 ; 0,2,3 -> 0, 255/4*3, 255 (=> t(L) = (L+1)/(max+1))
  note typically it is green on white bg similar to github theme.
- auto save, load at start localstorage. import, export. compact efficient save format
- get user commits to sync with image plan and suggest todays commit number
  related to yesterday (high and low levels to print image)
- if text add option subpixel smooth font - to not only use low and high commit
  numbers but also some other for grayscale antialiasing

## Constraints

- no build, no npm, no backend; evergreen browsers only; ES modules are fine
- local-only state; GitHub via public web APIs from the browser
- AGENTS.md style: tabs, flat control flow, no allocations in hot path

## Resolved Decisions

### Grid & date math

- Fixed `W = 53` columns, `H = 7` rows, `N = 371` cells. Index `i = col*7 + row`
  (column-major, like GitHub: column = week, row = weekday, row 0 = Sunday).
- Weeks start on Sunday (GitHub convention).
- The grid always spans 53 whole weeks. With offset `O` (whole weeks):
  - `endOfGrid = Saturday of this week + O*7 days`
  - `startOfGrid = endOfGrid - 52*7 days` (a Sunday)
  - `date(col,row) = startOfGrid + (col*7 + row) days`
- Offset slider: `-52 .. +52`, default 0. 0 = image ends this week (today inside the
  last column). Positive shifts the image into the future (plan next year's profile),
  negative shifts into the past (compare with history).
- "Today" cell = the cell whose date equals local today; it gets a dark outline.
  Cells after today are *future*: drawn dimmed. If today is outside the grid
  (large offset) there is no today marker and the suggestion box says so.
- All per-cell derived data (date key `YYYY-MM-DD`, tooltip label, month label,
  future flag, today flag) is precomputed once per offset change into reused typed /
  plain arrays — never inside the draw loop.

### Levels, color, commits — one shared normalization

- `Uint8Array(N)` stores raw levels 0..10. `max` is derived from data:
  `max = maxCell(grid)`, never stored, so the format stays tiny.
- Normalization (matches draft examples exactly):
  - `t(0) = 0`
  - `t(L) = (L+1) / (max+1)` for `L >= 1`
  - check: max=1 -> L1 => 1 (full); max=3 -> L2 => 3/4, L3 => 1 (the 255/4*3 example)
- Color (GitHub light theme): anchors
  `#ebedf0 #9be9a8 #40c463 #30a14e #216e39`.
  - display mode "gradient" (default): piecewise-linear interpolation across the
    anchors at `u = t*4`.
  - display mode "github": quantized to the 5 anchors `q = round(t*4)`.
  - level 0 always draws the empty anchor; future cells draw the empty anchor at
    reduced opacity.
- Commits per level (the actual point of the tool):
  - `commits(0) = 0`
  - `commits(L) = round(low + (high-low) * t(L))` for `L >= 1`
  - user sets `low` / `high` commits (defaults 1 / 10). `L = max` always maps to
    `high`. Same `t` as color, so what you see is what you commit.
- Paint amount slider: 1..10. Painting a level above current max grows max
  automatically (relative re-coloring happens). Erasing the only max cell shrinks max
  (recomputed on every dirty, 371-op scan — not hot enough to optimize).

### Tools & interaction

- Tools: Draw, Erase, Rect (separate tool, drag with live preview, fills on pointerup).
- Fill: whole grid to current amount. Clear: whole grid to 0.
- Undo: in-memory stack of 20 snapshots (grid copy + offset), pushed at stroke start /
  discrete action, `Ctrl/Cmd+Z` to pop.
- Pointer: `pointerdown/move/up/cancel` + `setPointerCapture`; works for mouse and
  touch. Canvas CSS-scaled responsive; convert via `logicalW / rect.width`.
- Hover tooltip (plain div): date label, level x/max, ~N commits, actual N if fetched,
  "future" tag.
- Keyboard: `1..9` / `0` set amount 1..10, `D` draw, `E` erase, `R` rect, `F` fill,
  `C` clear (confirm), `Ctrl+Z` undo. Ignored while typing in an input.

### Text

- Input line + style select + Render button. Styles:
  - `pixel 5x7`: built-in bitmap font (A-Z 0-9 + common punctuation), cell-exact,
    painted at level = current max (or 1 if grid empty).
  - `pixel 3x5`: smaller bitmap font (3 wide + 1 col spacing = advance 4), for longer
    text; occupies the middle 5 rows with 1 row padding top/bottom.
  - `smooth`: offscreen canvas at 4x grid resolution, bold system sans, sized to fit,
    downsampled per cell: average alpha over the cell's square -> coverage 0..1 ->
    level = round(coverage * maxEff), coverage < 0.12 -> 0. `maxEff = max(max, 4)` so
    antialiasing always has >= 4 levels.
- Composite: checkbox "replace" (default) overwrites grid; unchecked merges with
  `max(old, new)`.
- Unknown characters render as `?`.

### Storage & import/export

- One canonical string format, also used for localStorage auto-save:
  `GTM1|<offset>|<base64(Uint8Array(371))>` — ~510 chars total (max is derived,
  not stored).
- Auto-save: any grid/offset change debounces 300ms ->
  `localStorage['gtm-v1']`. Loaded on start (corrupt -> empty, keep original).
- Export button: copies the GTM1 string to clipboard AND downloads `timeplot.gtm`.
- Import accepts, in order: GTM1 string, JSON `{v:1, off, data}` (data base64 or
  array), plain text of 371 numbers (any whitespace/comma/semicolon separators).
  Rejects anything else with an error message in the status line.
- Import: file picker + "paste" prompt.

### GitHub sync & suggestion

- Inputs: username, optional PAT (kept in memory only, never persisted).
- Provider chain, first success wins:
  1. `https://api.github.com/graphql` `contributionsCollection` (only with PAT —
     GraphQL always requires auth) — exact contribution counts, full range.
  2. `https://github-contributions-api.deno.dev/<user>.json` — no auth, full last
     year, third-party (may be down).
  3. `https://api.github.com/users/<user>/events/public` (3 pages) — no auth,
     approximate: sum `PushEvent.payload.size` per day, recent months only. Flagged
     "approx" in the UI.
- Result: `Map<YYYY-MM-DD, count>` for the grid's date range (± a week), cached
  `localStorage['gtm-calc-<user>']` with 6h TTL.
- Overlay: cells with actual > 0 get a small amber dot (bottom-right). Tooltip adds
  "actual N".
- Suggestion box (updated on offset / low / high / grid / fetch change):
  ```
  Today  Mon Sep 21 · level 3/4 -> ~7 commits
  Yesterday Sun Sep 20 · planned 2 (~5) · actual 5
  ```
  "Yesterday" row shows actual vs planned to calibrate expectations (the draft's
  "related to yesterday"). If today's level is 0: "no commits needed today". If
  today is outside the grid: says the image is offset by N weeks.
- Fetch failures show the error in the status line; the low/high mapping still works
  without any fetched data.

### Canvas & rendering

- No animation loop. On-demand draws batched through a single `requestAnimationFrame`
  flag.
- Layout: 30px left gutter (Mon/Wed/Fri labels), 18px top gutter (month labels),
  cell 16px + 3px gap (pitch 19). Logical size 1037x151, backing store x DPR,
  `ctx.setTransform(dpr,...)`, CSS `width:100%;max-width:1037px`.
- Per draw: white bg, cached month labels, day labels, 371 cell fills from a
  precomputed `rgbCache[level]` string array (rebuilt only when max/display mode
  changes), today outline, actual dots, rect drag preview.
- `getImageData` context created with `willReadFrequently: true`.

### File layout

- `index.html` — markup + inline CSS.
- `core.js` — pure logic, no DOM: constants, date math, normalization, palette,
  font tables, serialization, commit math. Importable from node for tests.
- `app.js` — DOM, canvas, events, storage, fetchers. Imports `core.js`.
- `experiments/core-test.js` — plain-node assertions (`node experiments/core-test.js`).

## UX Layout

```
[Header: title | github user [__] token [____] [Fetch] | Export Import]
[Canvas: 53x7 grid, month labels top, Mon/Wed/Fri left, tooltip]
[Text: [__________] (pixel 5x7 | pixel 3x5 | smooth) [x replace] [Render]]
[Tools: (Draw)(Erase)(Rect)  Amount [slider 1-10] (3)  Fill Clear Undo
        Display (gradient | github)]
[Time: Offset [slider -52..+52] (0)  start 2025-10-05 -> end 2026-09-26]
[Mapping: low [1] high [10] commits | suggestion box]
[Footer legend: swatch per level 0..max with ~commits each]
```

## Implementation Phases

1. `core.js` + node tests (date math, t-formula, palette, codec, commit math, fonts).
2. `index.html` layout + `app.js` canvas render of an empty grid.
3. Paint tools (draw/erase/rect), amount slider, fill/clear, undo, tooltip, keyboard.
4. Text: font tables, pixel render, smooth offscreen render, replace/merge.
5. Storage: auto save/load, export (clipboard+file), import (3 formats).
6. GitHub: fetchers, cache, overlay dots, suggestion box.
7. Polish: legend, status line, error states, responsive check, `node --check` both
   modules, final manual pass.

## Validation Plan

- `node experiments/core-test.js` all green:
  - 371 cells; grid start is a Sunday; offset shifts dates by exactly O weeks;
  - t(1,max1)=1, t(2,max3)=0.75, t(3,max3)=1; ramp(0) = #ebedf0, ramp(1) = #216e39;
  - GTM1 round-trip on random grids; plain-number import;
  - commits(0)=0, commits(max)=high, monotone in L;
  - font table well-formed (all glyphs correct height); text width math.
- Manual (in browser preview):
  - paint a stroke, refresh -> persists; clear after export+import restores image;
  - "HI" readable in 5x7; "HELLO WORLD" in 3x5; smooth "hi" shows intermediate
    greens;
  - offset slider moves month labels + today marker; footer/suggestion follow;
  - amount 10 then amount 1 -> relative colors change; display toggle quantizes;
  - fetch a username (e.g. torvalds) without token -> overlay dots + actual in
    tooltip; suggestion box shows today level -> commits;
  - retina: grid lines crisp; no console errors.

## Risks & Mitigations

- Third-party deno API down -> provider chain falls through to events/public,
  error visible, tool still usable without fetch.
- CORS: REST api.github.com sends `Access-Control-Allow-Origin: *`; GraphQL requires
  a user PAT (optional field).
- Canvas antialias differences between browsers -> downsampled coverage is robust;
  test Chrome/Firefox.
- Pointer capture lost (e.g. context menu) -> `pointercancel` ends stroke.
- localStorage quota -> payload ~520 B, no risk.

## Out of Scope (0.2.0 candidates)

- PNG export of the rendered grid image; dark theme; pushing commits automatically;
  variable grid width; per-cell manual commit override.
