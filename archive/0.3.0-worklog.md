# 0.3.0 worklog — commit plan panel + auto font fit

## What was built

Two follow-ups from the draft: the single-day suggestion became a real schedule,
and pixel text no longer clips silently.

### 1. Commit plan panel

New row under the mapping row: `commit plan | days [7/14/30] | [x] carry shortfall`
plus a summary line and a wrapping row of day chips.

- Rows start at **today** and walk forward one day each until `days`, the end of the
  grid, or the preallocated row list runs out — whichever comes first.
- Per row: `target = commitsForLevel(level, max, low, high)` (the same normalization
  the colors and legend use), `actual` (synced, or `-1` for "unknown"),
  `left = target - max(0, actual)`.
- Carry: with sync data and the checkbox on, the unmet commits of the previous
  `CARRY_DAYS = 7` days are summed (`shortfallOf`) and added to today's `left`. A
  date missing from the map counts as 0 commits.
- Summary: `6 days · 38 commits on 5 days`, plus `· behind 12 over the last 7 days`
  when the carry applies. When today is off grid the panel says so and drops all
  chips.
- Chip: `today · Mon Sep 21` / `L2 · 8 commits` / status
  (`rest`, `rest · N done`, `planned`, `done ✓`, `N left`, `N done · M left`).
  Today's chip has a green ring (`today`), the met status is green (`met`), today's
  outstanding status is amber (`due`), non-working days are dimmed (`rest`).
  `title` explains the carry (`plan 8 commits + 7 carried from the last 7 days`).

### 2. Auto font fit

- `pixel auto` is the default text style: 5x7 while the line fits 53 columns
  (`textWidth57 <= 53`), else 3x5 (`textWidth35 <= 53`).
- When neither fits, `render` reports the needed width (`needs 79 columns in 3x5`)
  and leaves the grid untouched instead of drawing a clipped block.
- Status names the resolved font: `rendered text (3x5 auto)`.

## Notes / decisions

- Rows are forward-only. Yesterday belongs to the shortfall, not to the plan;
  including it would mix "done" with "planned" in the same total. Covered by the
  smoke test comment where painting yesterday changes only the shortfall.
- Absent dates count as 0 commits. That is only sound because every provider spans
  the grid range — noted in `findings-pitfalls-skills.md`, together with the
  "approx" label the events fallback already carries.
- Chips are DOM nodes created once per row-count change; refreshing after a painted
  cell only writes `textContent`/`className`. `innerHTML` is never rebuilt per paint.
- `refreshPlan()` lives next to `refreshSuggestion()` inside `refreshColors()`, so
  grid, max, low/high, import, undo and display changes all keep the panel in sync
  without extra call sites.
- The plan is derived state: nothing new is stored, the GTM1 format is unchanged.
- `days` and `carry shortfall` are session-only; they are presentation choices, not
  part of the saved image.
