# 0.2.0 - plan

## Goal

Two improvements on top of 0.1.0:

1. **Plot-width offset slider under the plot** — the offset is the most-used
   control but is currently a tiny browser-default slider crammed in a form row.
   Make it a wide track exactly the same width as the plot, drawn under the
   canvas, with a today marker so the user always sees where "now" sits.

2. **PNG export of the rendered grid** — natural follow-up: the user painted an
   image and got commit-count suggestions, now they want a picture to share
   the plan with friends.

## Slider redesign

### Geometry

- A `<canvas id="track">` placed inside `#plotWrap`, right under `#plot`,
  same width and 32 px tall. Both are CSS-equal-width so the track aligns
  exactly with the plot columns.
- Logical height: 32 px, backing store x DPR.
- Plot logical width = `LABEL_W + W*PITCH = 30 + 53*19 = 1037`. The track
  logical width = `1037` too (matches the cell row, including the left gutter).
- The track has an inset of `LABEL_W` on the left so the active range
  (`-52..+52`) maps to the cell columns only, not the labels.

### Visual model

- A horizontal bar 6 px tall centered vertically.
- A vertical "today" tick at the midpoint (offset 0), 14 px tall, in dark
  foreground color, with a small "today" label above it. The user can see at
  a glance: "thumb to the right of today = future plan, left of today = past".
- End ticks at -52 and +52 weeks with labels "-52w" and "+52w".
- Tick marks every 13 weeks (quarter-year).
- The thumb: a 14x22 px rounded rectangle, sits centered on the bar, dark
  fill. Its x-position is `inset + (offset + 52) / 104 * usableWidth`.
- Hover preview: while dragging or hovering, a vertical guideline at the
  thumb x, a small floating label showing the resulting date range
  ("Oct 5, 2025 → Sep 26, 2026"). Updates as the user drags.

### Interaction

- `pointerdown` on track (anywhere) sets the offset to the corresponding week
  (jump-to-position).
- `pointermove` while down continues to update the offset.
- `setPointerCapture` so dragging works even when the cursor leaves the canvas.
- `pointerleave` clears hover state.
- `wheel` on the plot or track: `deltaY > 0` -> offset -1, `deltaY < 0` -> offset +1.
  Lets the user scrub through weeks without reaching for the slider.
- The previous `<input type="range">` is removed; the offset value is owned
  by the canvas-backed slider.

### State sync

- New precompute `trackDates` array of length 53: for each column c, the
  start-of-week date key when offset = -52 + c*2 (slider maps every 2 weeks
  to a column). Built once per offset change (same lifecycle as `cellKey`).
  This lets us show the column's date in the hover label cheaply.
- Slider thumb position derived from current `offset`.
- After any state change (import, undo, fetch that re-renders), redraw the
  track to keep it in sync.

### Accessibility

- The track canvas keeps focus via `tabindex="0"`; arrow keys nudge offset by 1,
  PageUp/PageDown by 4, Home resets to 0, End moves to +52 / -52 depending
  on modifier.
- Keyboard tooltip shows the resulting start/end date in the existing
  `#status` line.

## PNG export

### Trigger

- New "PNG" button next to the existing "export" button. Distinct so users
  who want the picture don't accidentally get the `.gtm` text file.

### Output

- Render at 2x resolution for retina friendliness.
- Same layout as the on-screen canvas, but with the empty background
  rendered as a solid white rect (no border, no padding) and 8 px of
  outer margin so the picture isn't flush to the edges.
- Filename: `timeplot-<startISO>-<endISO>.png`, e.g.
  `timeplot-2025-09-21-2026-09-26.png`. Useful when a user has several
  planned offsets saved.

### Implementation

- Pure logic in `core.js`: `renderGridPNG(grid, opts) -> Blob`. Reuses the
  same color cache + date precompute the on-screen canvas uses, so the PNG
  is byte-for-byte the same picture (modulo DPR scaling).
- `app.js` calls into core, turns the blob into a data URL, triggers
  download with a hidden anchor, shows status.
- No new dependencies. `OffscreenCanvas` is not used; we do
  `canvas.toDataURL('image/png')` on a fresh in-memory canvas.

### Failure modes

- If the canvas tainting API throws (it won't here since we don't load any
  external images), fall back to a status-line error.
- Large grids: 1037x151 x 2x = ~620 KB PNG worst case. Fine.
