# 0.3.0 - plan

## Goal

Two follow-ups on the draft: make the per-day suggestion a real *schedule*, and
stop pixel text from silently clipping.

1. **Commit plan panel** — the coming days as a list: planned level, required
   commits, how many are already done today, how many are left. Optional carry
   of unmet commits from the last week into today's target (the draft's
   "suggest today's commit number related to yesterday").
2. **Auto font fit** — a `pixel auto` text style that picks 5x7 when the string
   fits 53 columns and falls back to 3x5, instead of clipping the message.

## Commit plan

### Semantics

- Row 0 is today; rows walk forward one day each, until `days` rows (7 / 14 / 30)
  or the end of the grid (index 371), whichever comes first. Rows never start
  before today, so the panel is always a plan, not a history.
- `target = commitsForLevel(level, max, low, high)` — the same normalization the
  colors and the legend use, so the panel and the picture can never disagree.
- `actual` is the synced commit count for that date, or `-1` when no sync data
  exists (then `actual` is displayed as unknown, not as zero).
- `left = target - max(0, actual)`, so it is 0 on days whose target is met.
- Shortfall: with sync data and carry enabled, unmet commits of the previous 7
  days are summed and added to today's `left`. Days absent from the map count as
  0 commits — the fetchers cover the whole grid range, so an absent date really
  means "nothing committed". Without sync there is no carry (nothing is known).
- Totals for the header: sum of targets (`total`) and number of days with a
  target (`dueDays`).

### core.js API

Pure, node-testable, no allocation in the caller's refresh path — the plan
record and its rows are owned by the caller and mutated in place:

```js
// plan = { rows: [{key,label,level,target,actual,left,today}], n, total, dueDays, shortfall }
buildCommitPlan(grid, cellKey, cellLabel, todayIdx, days, max, low, high, actualMap, carryDays, plan)
shortfallOf(grid, cellKey, actualMap, fromIdx, toIdx, max, low, high)
```

- `buildCommitPlan` returns `plan.n`; `0` when today is outside the grid.
- Row count is `min(days, 371 - todayIdx, rows.length)`.

### app.js

- One `plan` record + 30 preallocated rows, built at load.
- `refreshPlan()` recomputes and updates chips **in place**. Chips are DOM nodes
  created once per shape change and then only have `textContent` / `className`
  written — no `innerHTML` per painted cell.
- Refreshed from: init, `setOffset`, `refreshColors` (grid, max, low, high,
  import, undo, display change), fetch success, and the panel's own controls.
- Sync: `#planDays` (7/14/30), `#planCarry` checkbox (`CARRY_DAYS = 7`).

### UI

- New row under the mapping row: `commit plan | days [14] | [x] carry shortfall`
  then the summary text, then the chips (own flex line).
- Chip: `Mon Sep 21` / `L3 · 7 commits` / status. Status text:
  - `rest` — target 0 (shows `rest · N done` when commits happened anyway),
  - `planned` — no sync data,
  - `done ✓` — synced, target met,
  - `N left` or `N done · M left` — work remains.
- Today's chip is prefixed `today ·` and gets a green ring; `met` turns the
  status green, `due` on today turns it amber, `rest` dims the chip.
- Chip `title` carries the breakdown (`plan 8 + 7 carried`).
- Summary: `6 days · 38 commits on 5 days` plus `· behind 7 over the last 7
  days` when sync data with carry is present. Empty state when today is off
  grid: `today is outside the grid — move the offset so today is visible.`

### Edge cases

- Today off grid (large negative offset) → no chips, empty-state summary.
- Grid ends before `days` → fewer chips, no padding rows.
- No sync → `actual = -1`, status `planned`, carry has no effect.
- Every mutation path (paint, offset, low/high, import, undo, fetch) refreshes
  the panel.

## Auto font fit

- `pickPixelFont(text)` in core: `'57'` when `textWidth57 <= 53`, else `'35'`
  when `textWidth35 <= 53`, else `null`.
- `pixel auto` becomes the first (default) option of the text style select.
- `render` resolves `auto`; if neither font fits, it reports the width needed
  and leaves the grid untouched instead of drawing a clipped block.
- Status line names the resolved font: `rendered text (3x5 auto)`.
